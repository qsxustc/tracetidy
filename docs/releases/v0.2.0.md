# TraceTidy v0.2.0 — network triage and reviewed sharing

TraceTidy turns a browser network capture into a reviewable bug report. Inspect a HAR on your device, investigate failed or slow requests, then export a sanitized HAR, a Markdown issue report and a redaction audit. Processing stays in the browser; no account, API key or backend is required.

**[Try the public demo](https://tracetidy-lab-qsx.cherryboar4.chatgpt.site/)** · **[Inspect the source](https://github.com/qsxustc/tracetidy)**

The demo is available without login. Start with its built-in synthetic capture to explore the workflow.

## What's new

- **Clickable triage observations.** See network failures, HTTP 4xx/5xx responses, slow waiting/receiving phases and repeated endpoints. Select an observation to inspect the matching requests. These describe recorded patterns and do not establish a root cause.
- **Endpoint groups.** Group requests by method, origin and path, with call/error counts, P95, average and summed duration. Query values do not split groups. Filters select visible groups; metrics cover the complete trace.
- **Reproduction context.** Add a title, reproduction steps, expected behavior and actual behavior to the issue report before exporting the share pack.
- **Background processing and cached exports.** Parsing, analysis, sanitization, report serialization and ZIP generation run in a module Web Worker. Existing successful exports are reused across tabs and downloads.
- **Reliable session changes.** Changing sharing rules disables export until the newest snapshot succeeds. Clearing or replacing a trace cancels processing and discards obsolete results. Request selection and tab navigation retain keyboard focus.
- **Repeatable synthetic measurements.** `npm run benchmark` reports core processing costs using generated data. The documentation separates those measurements from browser behavior.

## Downloads and local use

| Asset | Contents / use |
| --- | --- |
| `tracetidy-v0.2.0-source.tar.gz` | Tracked public source, CLI, tests and documentation under `tracetidy-0.2.0/`. No dependency installation is required. |
| `tracetidy-v0.2.0-web.tar.gz` | Built static browser app and MIT license notice, with `index.html` at the archive root. Deploy the extracted contents to static HTTPS hosting. |
| `SHA256SUMS` | SHA-256 checksums for both archives. |
| `release-manifest.json` | Version, source commit and archive names, byte sizes and SHA-256 checksums. |

For the source archive, use **Node.js 20 or newer**:

```sh
tar -xzf tracetidy-v0.2.0-source.tar.gz
cd tracetidy-0.2.0
npm start
```

Open the local URL printed by the server and try the included synthetic demo. The CLI uses the same sanitizer:

```sh
node bin/tracetidy.js samples/demo.har --output safe.har --report issue.md --audit audit.json
```

The static app needs HTTPS or a local HTTP server and a browser with module Web Workers. Opening `index.html` with `file://` is unsupported. This release has zero runtime dependencies and is MIT licensed. It is not published to npm.

To check the downloaded archives on macOS:

```sh
shasum -a 256 -c SHA256SUMS
```

## Validation and boundaries

The release candidate passed **58 automated tests**: 52 core, processor, CLI and ZIP regressions plus six release-packaging tests covering archive inputs, hashes and overwrite protection. The static build also passed. Browser checks on macOS used a synthetic **23.15 MiB / 10,000-request** HAR: import, 50-row pagination, rule changes, cancellation, request filters, endpoint groups and share-pack download worked. The downloaded ZIP's CRCs and three files were checked, including the absence of planted HAR credentials.

These checks apply to those workloads and that environment. They do not establish frame rate, an end-to-end speedup or broad browser compatibility. See [performance details](https://github.com/qsxustc/tracetidy/blob/v0.2.0/docs/PERFORMANCE.md).

**Review exports before sharing.** TraceTidy uses deterministic heuristic redaction, and retained timings, status codes, methods and sizes can still reveal context. Default exports remove bodies, cookies, sensitive headers and unknown HAR fields, and use stable endpoint aliases without exporting a mapping. Preserving routes can reveal endpoint identities. Missing duration is reconstructed from recorded phases or treated as zero, which can understate latency statistics.

**Written reproduction notes are included as entered.** HAR redaction terms do not scrub those fields. Inspect the report and exported HAR before posting them. The browser accepts up to 25 MiB; shared core validation caps source text at 50 MiB, requests at 50,000 and individual URLs at 32 KiB. Processing is in memory, and those are input limits rather than memory-use guarantees. See the [security model](https://github.com/qsxustc/tracetidy/blob/v0.2.0/docs/THREAT-MODEL.md).
