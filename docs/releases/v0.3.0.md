# TraceTidy v0.3.0 — compare recordings before sharing

TraceTidy now compares a baseline HAR with the current recording. Use it after a fix, a frontend change, or a deployment to inspect which endpoints slowed down, improved, appeared, disappeared, or returned more failures. Processing and matching stay in a local Web Worker; no account, API key or backend is required.

**[Try the public demo](https://tracetidy-lab-qsx.cherryboar4.chatgpt.site/)** · **[Inspect the source](https://github.com/qsxustc/tracetidy)** · [Latest packaged release: v0.2.0](https://github.com/qsxustc/tracetidy/releases/tag/v0.2.0)

These notes describe the v0.3.0 source update. The download link above continues to point to the existing v0.2.0 packaged release.

## What's new

- **Baseline comparison.** Import a current HAR, open **Compare captures**, then import an earlier recording. The summary compares request counts, P95, failure rate and response bytes; endpoint rows show matched call counts, P95 changes and failure rates.
- **Adjustable regression rules.** The default latency rule requires both a P95 increase of at least 100 ms and at least 20% of baseline P95. Any failure-rate increase also classifies the endpoint as regressed. Regression evidence takes priority if latency and failures move in different directions. Latency improvements use the same two thresholds and the baseline denominator.
- **Search, filters and request navigation.** Search endpoints by method or URL, select regressed, improved, added, removed or unchanged groups, and click a group to inspect its matching requests in the current recording. Filters affect the browser view; summaries and exports cover the complete pair.
- **Synthetic baseline.** Open the existing current demo and choose **Try sample baseline**. The two synthetic recordings include regressions, improvements, added calls and removed calls, without real customer data.
- **Anonymous comparison export.** Download `comparison.md` or include it in the share pack beside `safe.har`, `issue.md` and `audit.json`. The report exports numeric metrics and anonymous endpoint IDs, with no original routes, hosts, baseline file or alias mapping.
- **Bounded header previews.** The request inspector limits original header previews before assembling and escaping their strings, and displays a truncation notice. Oversized headers no longer require building their full combined preview on the main thread.

## Matching and interpretation

Matching uses the normalized method, origin and exact path. Query strings and fragments are excluded; protocol, host, port, method and trailing-slash differences create separate groups. Added and removed endpoints are separate classifications because they have no paired latency evidence.

Failures include HTTP 4xx/5xx and status 0. P95 uses nearest rank over normalized durations. Missing total time uses recorded phases, with SSL excluded to avoid double counting; entirely unavailable timings become 0 and can understate latency. A zero baseline has no relative percentage change. Response bytes use HAR `bodySize` when available, otherwise `content.size`. Summed durations include overlapping requests and are not wall-clock duration.

Compare the same workflow under similar conditions. Small samples, differing request counts, warm caches and network conditions can move P95 and failure rates. These classifications report recorded differences; they do not establish a code regression, root cause or statistical significance.

## Export and session boundaries

`comparison.md` always uses anonymous `endpoint-N` IDs, including when route preservation is enabled for `safe.har`. The IDs identify a matched group within the pair but are independent of `safe.har`'s `host-N` and `route-N` aliases. There is no exported mapping between them.

The report includes complete recording totals and classification counts, then up to **100 endpoint rows** by priority: regressed, added, removed, improved, unchanged; ties use P95 increase and endpoint identity. The browser table can inspect all groups. Neither endpoint filters nor current request filters change the exported report.

The baseline is retained only in the local Worker's memory. Importing a new current recording, removing the baseline, clearing the session, or reloading/closing the tab discards the baseline and comparison. The baseline is not stored in the browser or included in the share pack. Processing, comparison-rule changes and downloads discard stale results when the session changes.

The HAR, issue report and audit continue to come from one sanitized snapshot. Written reproduction context is included as entered; HAR custom redaction terms do not scrub those fields. Review the reports and HAR before sharing. Anonymous comparisons still reveal methods, timings, status patterns and sizes.

## Local use and checks

Use Node.js 20 or newer. From the repository directory:

```sh
npm start

# Automated behavior checks and static build.
npm test
npm run build
```

The browser app uses native modules and module Web Workers. Serve it over local HTTP or hosted HTTPS; opening `index.html` through `file://` is unsupported. The synthetic recordings are [samples/demo.har](../../samples/demo.har) and [samples/baseline.har](../../samples/baseline.har). The project has zero runtime dependencies, uses the MIT license and is not published to npm. Baseline comparison is available in the browser app; CLI exports still process one recording.

Automated comparison coverage checks endpoint identity, nearest-rank P95, threshold boundaries, mixed failure/latency changes, missing timings, status 0, response-byte fallback, deterministic aliases, input preservation and anonymous Markdown. Worker and processor checks cover comparison lifecycle, stale responses and ZIP inclusion; header-preview checks cover character and header limits. Run the commands above for the current source tree's results.

默认延迟回退规则要求**同时满足 P95 增加至少 100 ms，且增加量达到基线的 20%**；失败率只要上升，也会标记为回退。改善使用相同阈值和基线分母，指标方向冲突时优先标记回退。匹配要求方法、origin 和精确路径相同，忽略查询参数与 fragment。请比较相同流程和近似环境；样本大小、缓存和网络变化可能影响结果，分类不能证明代码回退或统计显著性。

可以单独下载 `comparison.md`，有完成的对比时也会加入分享 ZIP。报告始终隐藏原始域名和路径，使用独立的 `endpoint-N` 编号，**这些编号与 `safe.har` 的路由别名不同，也不导出映射**。完整汇总之后，最多列出 100 个接口，按变化优先级和 P95 增加量排序；浏览器内可以检查全部分组。
